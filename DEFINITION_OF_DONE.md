# Definition of Done for a Report

This document outlines when a report related to contrast-plus should be considered complete.

The report is done only when all of the following are true:

## 1. Purpose and scope are clear

- The report states what question, feature, issue, or audit it covers.
- The intended audience is clear.
- Any in-scope and out-of-scope items are explicitly listed.

## 2. The report is accurate and evidence-based

- Claims are supported by direct observation, repository evidence, test results, or cited references.
- Reported metrics, calculations, screenshots, or examples match the current state of the project.
- Assumptions are stated plainly.

## 3. The report reflects project values

- The report treats contrast-plus as an educational and assistive tool, not a certification service.
- The language does not imply that a single metric guarantees accessibility.
- Any mention of WCAG, APCA, or related thresholds is clearly identified as guidance, context, or measured output.

## 4. Findings are actionable

- Each finding explains the problem, why it matters, and what should happen next.
- Severity or priority is assigned when appropriate.
- Recommended follow-up work is specific enough for a contributor to act on it.

## 5. Accessibility is considered in the report itself

- The report uses clear headings and logical structure.
- Tables, screenshots, and examples include enough context to be understood without color alone.
- Important limitations or risks are described in text, not only visually.

## 6. Limitations are explicit

- Unknowns, gaps, and unresolved questions are documented.
- Any missing test coverage, unavailable data, or manual-review needs are called out.
- The report distinguishes confirmed issues from hypotheses or suggestions.

## 7. Validation is documented

- The report records which checks were run and what their outcomes were.
- Manual review steps are noted when relevant.
- If checks could not be run, the report explains why.

## 8. The output is review-ready

- The report is written in plain language.
- Terminology is consistent with the rest of the project.
- Spelling, formatting, and links have been reviewed.

## 9. Repository impact is complete

- Any related documentation updates are included.
- Any needed issue, PR, or follow-up references are linked.
- The report can be understood on its own by a future contributor.

## Final checklist

A report is ready when it is:

- Clear about purpose and scope
- Factually supported
- Honest about limitations
- Actionable for contributors
- Accessible to read and review
- Consistent with contrast-plus project principles
